## What this project is

Swedish electricity spot price and power monitoring dashboard — a vanilla JS Progressive Web App that polls a Raspberry Pi backend (`sotehus-pi5:8080`) every second and displays real-time grid consumption, solar production, spot price, and grid frequency.

## Commands

```bash
# Development (serve src/ directly, no build step needed)
npm run dev          # serves src/ on a random port via `npx serve`
# OR
cd src && python3 -m http.server 8000

# Production build (copies src/ → dist/ and stamps version into sw.js)
npm run build

# Serve production build
npm start            # serves dist/ on a random port

# Docker (recommended for production)
docker compose up -d --build
docker compose logs -f
docker compose down
```

There are no tests and no linter configured.

## Architecture

The entire frontend lives in `src/` with no bundler or framework. JS is split into native ES modules (loaded via `<script type="module" src="/js/app.js">`), one per concern:

- **`src/js/config.js`** — `CONFIG` holds `API_BASE_URL`, `REFRESH_INTERVAL`, and `VERSION`.
- **`src/js/state.js`** — shared `isOnline` live binding, updated via `setOnline()`.
- **`src/js/dom.js`** — the `elements` cache and `initElements()`.
- **`src/js/format.js`** — timestamp/power/ISO formatting helpers.
- **`src/js/dashboard.js`** — dashboard card fetch/render + `startRefresh`/`stopRefresh`.
- **`src/js/solis.js`** — Solis power-flow view fetch/render + its own refresh loop.
- **`src/js/weather.js`** — weather station view fetch/render + its own refresh loop.
- **`src/js/cost.js`** — cost view fetch/render and the Chart.js cost chart.
- **`src/js/settings.js`** — params fetch/render/save.
- **`src/js/views.js`** — `showDashboardView`/`showSolisView`/`showWeatherView`/`showCostView`/`showSettingsView`, coordinating which feature module's refresh loop is active.
- **`src/js/menu.js`** — hamburger menu open/close.
- **`src/js/pwa.js`** — service worker registration, install prompt, online/visibility handling.
- **`src/js/meta.js`** — backend version + location name fetch for header/footer.
- **`src/js/app.js`** — entry point; wires DOM, menu listeners and view navigation together, then starts the dashboard refresh loop.

When adding a new JS module, also add it to `STATIC_ASSETS` in `src/sw.js` so it's precached.

- **`src/sw.js`** — service worker template; `__VERSION__` placeholders are replaced by `npm run stamp-version` using the `VERSION` from `config.js`. Static assets use cache-first; API calls use network-first.
- **`src/index.html`** — all views (dashboard, cost, blocks, settings, solis) are present in the DOM simultaneously and toggled via CSS `hidden` class.
- **`src/css/styles.css`** — theme colors as CSS variables; supports automatic dark mode via `prefers-color-scheme`.

### View system

There is no router. Views share the DOM: `dashboardView`, `costView`, `blocksView`, `settingsView`, `solisView`, `weatherView`. Navigation functions (`showDashboardView`, `showCostView`, `showSettingsView`, `showSolisView`, `showWeatherView`) add/remove the `hidden` class and start/stop the relevant polling timer as appropriate.

### API integration

All API calls target `CONFIG.API_BASE_URL` (defaults to `http://sotehus-pi5:8080/api`). Key endpoints:
- `GET /api/data` — real-time dashboard data (called every second)
- `GET /api/energy/cost?start=...&stop=...` — cost report with price period blocks
- `GET /api/params` / `PUT /api/params/{key}` — configurable backend parameters
- `GET /api/version` — backend version for footer display
- `GET /api/weather` — latest weather station readings (`readings` map of name → `{value, unitOfMeasure}`), polled every `CONFIG.WEATHER_REFRESH_INTERVAL`

The cost view uses `formatLocalISO()` to send timezone-aware ISO timestamps matching Swedish local time.

### Build / deploy pipeline

`npm run build` does two things: copies `src/` to `dist/`, then stamps the version string from `config.js` into `sw.js` (replacing `__VERSION__`). The `dist/` directory is a build artifact (gitignored) regenerated by `npm run build`. GitHub Actions builds a multi-arch Docker image (`linux/amd64`, `linux/arm64`) and pushes to GHCR on every push to `main`.

### Versioning

Bump `CONFIG.VERSION` in `src/js/config.js` — the build script propagates it to the service worker cache name automatically. This invalidates all caches on the next deploy.

### Chart library

`Chart.js` is loaded from CDN in `index.html`. The cost blocks view renders a combo bar+line chart via `renderCostChart()` in `src/js/cost.js`, with a stored instance reference (`costChartInstance`) destroyed before re-rendering.
